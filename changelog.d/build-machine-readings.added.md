The collector checks the five `details` keys microcosm-emitter writes itself (a heartbeat's `reading` and `sleep`, a run start's `environment`, a stage's `stage_span` and progress's `outer`) and serves them in read API v1: `run_manifest.environment`, `progress.reading` (the current attempt's latest reading, with its time) and a top-level `sleeps` list. A key that doesn't match its model is removed from the stored event and named in `details.dropped_emitter_details`, and the rest of the event is accepted (microcosm-collector#46).
