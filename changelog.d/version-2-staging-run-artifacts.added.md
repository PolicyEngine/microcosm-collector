- The collector reads the result files of a version 2 staging run under `runs/<id>/artifacts/`, where Microcosm's version 2 writer puts them and where US builds will write them (microcosm#1135). It copies `artifacts/reform_validation.json` for the dashboard beside the top-level `reform_validation.json` of version 1 runs, named by that path in the index. A structured run whose diagnostics are in its run folder has its tree built with the `build_manifest` and `release_manifest` its run manifest declares, each checked against its declared SHA-256, and one the folder lacks makes the run `unbuildable`; the tree stores copies of the `reform_validation` and `parent_build_manifest` the run declares, leaving out one the folder lacks or with another digest, also for a run whose diagnostics come from its staged dataset. A structured run never takes these files from its folder's top level, which only schema-1 runs use. `@policyengine/calibration-tree` 0.1.6 adds `artifacts/reform_validation.json` to `STAGING_RUN_FILE_NAMES` and `stagingReformValidationFileName`; `loadCopiedStagingRun` returns a structured run's declared reform validation only when its digest is the declared one, and never a top-level copy, and the Hugging Face staging reader reads the same declared paths. Readers of 0.1.5 read the new index without the new copy.
