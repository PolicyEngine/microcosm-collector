Add the `reproject-past-builds` operator command, which publishes Orrery graph files for past builds made after microcosm#1151 whose staged folder holds a graph schema and an execution overlay. For each such build in the inventory of past builds it makes the `orrery-inputs` submission the build would have sent, owned by `microcosm-collector`. The submission holds the folder's schema, overlay and upstream files, read at the inventory's revision. Its provenance gives the build's run ID as run and build ID, its country as Microcosm registers it (`GB` for `uk`), and the Hugging Face folder at the newest last commit among the submitted files (`HuggingFaceReader.last_commits`). `licensed_data` is true unless the build was staged in a public dataset. The submission ID is the request's hash, so a second run changes nothing unless a submitted file changed. A file over its role's size limit refuses the build before anything is downloaded. The command creates the files create-only in the intake bucket (`GoogleCloudStorageIntake.create_object`), accepts the submission as completion does, and runs its job at once through the worker's `run_job`, so the document is validated, published and recorded as a new build's is; a job an earlier run left `processing` is run again. Each build's outcome is printed as it is produced; an error in one build is its `error` outcome, the next build is still projected, and the command then exits non-zero. Every other build is listed as `left_out` with the reason, and `--dry-run` lists what would be projected, downloading and writing nothing. The command needs `DATABASE_URL`, `COLLECTOR_HF_READ_TOKEN`, `COLLECTOR_INTAKE_BUCKET` and `COLLECTOR_ORRERY_BUCKET`, and permission for the worker's account to create objects in the intake bucket for the run.
