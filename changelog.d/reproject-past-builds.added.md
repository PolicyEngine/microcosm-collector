Add the `reproject-past-builds` operator command, which publishes Orrery graph files for past builds made after microcosm#1151 whose staged folder holds a graph schema and an execution overlay. For each such build in the inventory of past builds it makes the `orrery-inputs` submission the build would have sent, owned by `microcosm-collector`. The submission holds the folder's schema, overlay and upstream files, read at the inventory's revision. Its provenance gives the build's run ID as run and build ID, its country as Microcosm registers it (`GB` for `uk`), and the Hugging Face folder at the newest last commit among the submitted files (`HuggingFaceReader.last_commits`). `licensed_data` is true unless the build was staged in a public dataset. The submission ID is the request's hash, so a second run changes nothing unless a submitted file changed. Each build is first checked from Hugging Face's listings (the submission rules with the listed sizes, the Orrery handler's 32 MiB input limit, and a last commit for each submitted file) before anything is downloaded, and each download must match its listing's size and SHA-256 or git blob ID. The command creates the files create-only in the intake bucket (`GoogleCloudStorageIntake.create_object`), accepts the submission as completion does, and runs its job at once through the worker's `run_job`, so the document is validated, published and recorded as a new build's is; a task retry continues a job its killed attempt left `processing`. Each build's outcome is printed as it is produced, then a summary of the run; an error in one build is its `error` outcome and the next build is still projected. The command exits non-zero when any build is incomplete: an `error`, or a build left out because GitHub stopped answering before it was classed. The inventory of past builds now marks such builds with `class_retry_later`. Every other build is listed as `left_out` with the reason, and `--dry-run` makes the same checks and lists what would be projected, downloading no graph inputs and writing nothing. The command needs `DATABASE_URL`, `COLLECTOR_HF_READ_TOKEN`, `COLLECTOR_INTAKE_BUCKET` and `COLLECTOR_ORRERY_BUCKET`, and permission for the worker's account to create objects in the intake bucket for the run.
