A calibration tree built from a release build's submission now becomes its country's latest only when the release repo's `releases.json`, read at the repo's head commit under the manifest lock just before the publication, names it as its default release's current build, for every country the collector lists, as the GitHub Actions publisher decides. A repo without `releases.json` (a 404 without `RepoNotFound` or `RevisionNotFound`) keeps the `DEFAULT_RELEASES` rule. Any other failed read of `releases.json` returns the job for another attempt before anything is published; a `releases.json` that breaks the record's rules publishes the tree without moving the latest, and the result records `latest_skipped: "releases_record_refused"` with the reason. The worker job's tree handler therefore needs `COLLECTOR_HF_READ_TOKEN` beside `COLLECTOR_CALIBRATION_TREE_BLOB_TOKEN`, and the worker stops with a message naming it when it is missing; the deploy already mounts both on the worker job.
