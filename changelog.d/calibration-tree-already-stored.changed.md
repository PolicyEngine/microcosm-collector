A `calibration-diagnostics` submission whose publication is refused because another writer already stored a tree for its build now succeeds instead of being rejected as `calibration_tree_refused`. The store's manifest is read after the refusal. A release build counts as stored when the manifest holds a tree of the same release build with the same build ID (a hash of the tree schema version, country, kind, source ID and each source file's SHA-256), and a staged run when it holds any tree of the same run: the reconcile command builds a staged bundle from its diagnostics alone, while its submission also sends its build manifest. The submission's result then says `already_stored: true` and `made_latest: false` and names the stored tree's `build_artifact_id` and its own `submitted_build_artifact_id`, and it moves no latest. The reconcile command reports such a build `already_stored` instead of `refused`. Any other refused build is still refused, and a manifest that can't be read then fails the attempt so it runs again.
