A `calibration-diagnostics` submission whose publication is refused because the store already holds its tree from the same files now succeeds instead of being rejected as `calibration_tree_refused`. The store's manifest is read after the refusal, and when it holds a tree of the same kind for the same release build or staged run with the same build ID (the SHA-256 of the same calibration diagnostics), stored first by the reconcile command, the backfill or another submission, the submission's result says `already_stored: true` and `made_latest: false`, and it moves no latest. The reconcile command reports such a build `already_stored` instead of `refused`. A refused build with another build ID, run or kind is still refused, and a manifest that can't be read then fails the attempt so it runs again.
