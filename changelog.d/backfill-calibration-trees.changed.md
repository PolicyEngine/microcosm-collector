A calibration tree built from a release build's submission now becomes its country's latest when the release repo's `releases.json`, read at the repo's head commit when the tree is built, names it as its default release's current build, as the GitHub Actions publisher decides. A repo without `releases.json` (a 404 without `RepoNotFound` or `RevisionNotFound`) keeps the `DEFAULT_RELEASES` rule, so the UK's builds keep their current behaviour while its pointer files stay. Any other failed read of `releases.json` returns the job for another attempt before its files are downloaded; a `releases.json` that breaks the record's rules publishes the tree without moving the latest, and the result records `latest_skipped: "releases_record_refused"` with the reason. The worker job's tree handler therefore needs `COLLECTOR_HF_READ_TOKEN` beside `COLLECTOR_CALIBRATION_TREE_BLOB_TOKEN`, and the worker stops with a message naming it when it is missing; the deploy already mounts both. A build made current later, or a change to `releases.json` with no new build, still doesn't move the latest through a submission, and the publication command still moves the latest only to a build at least as new as the current one.
