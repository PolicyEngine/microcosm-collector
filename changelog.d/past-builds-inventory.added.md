Add the `past-builds` operator command, which prints an inventory of past Microcosm builds as JSON and stores nothing: one entry for each `staged/<run_id>/` folder in each country's Hugging Face release dataset, read at the commit its `main` points at, and for each run in `telemetry_runs` (UK runs, which Microcosm registers as `GB`, listed as `uk`), joined by run ID. It prints a document with when the inventory was made, each dataset's revision and the totals, and then one document for each build. Each build gives its Microcosm commit, from its folder's `staged_manifest.json` (`summary.git_commit`) or else from its run's `run` events (`details.identity.git_commit`), with `commit_source` saying which; its class (`after_1151`, `between_1144_and_1151`, `before_1144` or `unknown`, with the reason), worked out with GitHub's compare API without a token, one or two requests for each distinct commit, with only that build `unknown` when GitHub has no such commit and every later commit `unknown` after a rate-limit answer or any other failure, and with staged builds that can be rebuilt checked first, newest first, then other staged builds, then recorded runs; the graph files the folder holds; and what can be rebuilt from Hugging Face (`full` with the schema and execution overlay, `declaration_only` with the schema alone, or `none`). Builds made before microcosm#1144, and builds made before microcosm#1151 with nothing to rebuild from, are listed as skipped, with the reason. `telemetry_collector.past_builds.list_past_builds` returns the same inventory to code. The command needs `DATABASE_URL` and `COLLECTOR_HF_READ_TOKEN`, so it runs as an execution of the worker job with its arguments overridden.
