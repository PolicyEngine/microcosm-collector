Switch artifact intake on in staging and production from the deployment. `scripts/deploy.sh` passes `COLLECTOR_INTAKE_ENABLED=1` and the other intake settings to both service revisions in both environments, and every release updates the worker and recovery Cloud Run jobs to the released image with their whole configuration, after the migration and before the candidate revision, without ever creating either job. Production's worker job mounts the collector's Hugging Face read token as `COLLECTOR_HF_READ_TOKEN`, listed with `DATABASE_URL` in one `--set-secrets`; staging's mounts none. Before anything changes, the deploy refuses an intake name the collector's own patterns would refuse, and a job that does not exist, runs as another service account than the deploy gives it, or connects to another environment's Cloud SQL instance; in production it also checks that the token's secret exists. The deploy reads seven new `TELEMETRY_*` variables in each environment, and `TELEMETRY_HF_READ_SECRET_NAME` in production; staging needs all seven created, production six, and a deploy without one stops before it authenticates.
