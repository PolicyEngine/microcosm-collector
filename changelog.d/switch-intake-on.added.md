Switch artifact intake on per environment from the deployment. `scripts/deploy.sh` passes the intake settings to both service revisions, with `COLLECTOR_INTAKE_ENABLED` taken from the environment's own `TELEMETRY_INTAKE_ENABLED`, which must be `0` or `1`, so staging's intake can be checked before production's is switched on. Every release updates the worker and recovery Cloud Run jobs to the released image with their whole configuration, after the migration and before the candidate revision, and never creates either job. Production's worker job mounts the collector's Hugging Face read token as `COLLECTOR_HF_READ_TOKEN`, listed with `DATABASE_URL` in one `--set-secrets`; staging's mounts none. Before anything changes, the deploy checks that both jobs exist and, in production, that the token's secret exists. Each environment needs eight new `TELEMETRY_*` variables, and production also `TELEMETRY_HF_READ_SECRET_NAME`; a deploy without one stops before it authenticates.
