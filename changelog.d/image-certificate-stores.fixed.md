Remove "emSign ECC Root CA - G3" and "AAA Certificate Services", the roots that the compromised eMudhra intermediate CA certificates chain to, from the image's own certificate stores. The image now upgrades Debian's `ca-certificates` to bookworm-security's 20250419~deb12u2, which drops both roots, and the system pip to 26.2.2 or later, whose vendored certifi 2026.10.19 lacks the first; the base image's `ca-certificates` 20230311+deb12u1 and pip 25.3 held them. The collector's Hugging Face check already verifies against the locked certifi and is unchanged, but any later `urllib` call, bare `ssl.create_default_context()` or installed curl would have trusted Debian's copies. CI now fails if any certificate file in the built image holds either root, matched by SHA-256 fingerprint, and the deployment runs the same check on the image it builds and pushes nothing that fails it.
